Nothing adds people yet: TASK-0040 (and TASK-0047 for the first Owner) fills both tables in one save.

## RULES FOR THE CODE YOU WRITE
1. **Schema** (`schema/users.ts`, with `core` from `./schemas.js`, `companies` from `./companies.js` and `roles` from `./roles.js`): exactly the columns, types, defaults, keys and links that `apps/api/test/db/users.test.ts` checks, in its order (read its first describe block).
   - `core.users`: `id` uuid, the key, with **no default** (it is the person's sign-in ID); `company_id` required, linked to `core.companies` with `onDelete: 'restrict'`; `display_name` text, required; `photo_file_id` uuid (no link: the files table comes with TASK-0069); `role_id` uuid, required; `signin_methods` a required text array with no default (`text('signin_methods').array().notNull()`); `manager_user_id` uuid; `switch_email_by` date; `last_signin_at` timestamptz; then `created_at`, `created_by`, `updated_at`, `updated_by`, `version`, `deleted_at`, `deleted_by` and `purged_at` as the test lists them. Keys and links: `unique('users_company_id_id_unique').on(table.companyId, table.id)`; `foreignKey({ columns: [table.companyId, table.roleId], foreignColumns: [roles.companyId, roles.id] })` and `foreignKey({ columns: [table.companyId, table.managerUserId], foreignColumns: [table.companyId, table.id] })`, both `.onDelete('restrict')`.
   - `core.user_preferences`: `company_id` required, linked to `core.companies` with `onDelete: 'restrict'`; `user_id` uuid, required; `language_code` text (empty means the company's language: the languages table comes with TASK-0067); `colour` of the enum `themeColour` (empty means the company's colour); `time_zone` text, required, default `'Asia/Kolkata'`; `time_format` of the enum `timeFormat`, required, default `'h12'`; `date_format` text, required, default `'DD MMM YYYY'`; `daily_summary_time` `time` (stored now; sent from Release 9); `updated_at` timestamptz, required, default `now()`. Key `primaryKey({ columns: [table.companyId, table.userId] })` (every unique key on a company table includes the company); link `foreignKey({ columns: [table.companyId, table.userId], foreignColumns: [users.companyId, users.id] }).onDelete('restrict')`.
   - Export `users`, `userPreferences`, `themeColour` (`core.enum('theme_colour', ['emerald', 'navy'])`) and `timeFormat` (`core.enum('clock_format', ['h12', 'h24'])`). The column is `time_format`, but its type is `clock_format`, never `time_format`: drizzle-kit 0.31.11 writes a type whose name starts with a built-in type's name (`time`, `text`, `date`...) without its schema, and the change would then fail with `type "time_format" does not exist`.
   - There is **no database link** from `core.users` to the sign-in tables, and the file never names them, not even in a comment (TASK-0032's wall test reads the text of every `.ts` file outside `src/db/`, `modules/core/signin/` and `modules/core/users/`).
2. **The step** (`signin/session.ts`): `export async function whoIsAsking(req: Request): Promise<void> {` (with `import type { Request } from 'express';`). It always asks Better Auth, once per request, with exactly `getAuth().api.getSession({ headers: fromNodeHeaders(req.headers), query: { disableRefresh: true, disableCookieCache: true } })` (`fromNodeHeaders` from `better-auth/node`): it never reads the cookie itself, it never refreshes the session (only the open sign-in door `GET /api/auth/get-session` does), and it never answers from Better Auth's cookie cache, so a disabled person is refused at once even if that cache is ever switched on. When there is no session, or the person's status is not `active` (TASK-0032's `status` field), or the person has no company (TASK-0032's `companyId` field), it throws exactly `new AppError(401, 'not_signed_in', 'Please sign in.')`. Otherwise it sets on the request's existing context (`const context = getContext();`, never `runWithContext`): `context.userId` = the person's ID, `context.companyId` = their company, `context.sessionId` = the session's ID. It never reads or keeps the session token, writes nothing, logs nothing, and catches nothing: an error from Better Auth or a missing setting answers 500 through the error handler. It never reads the lock (`lockedUntil`, TASK-0036): a lock stops new password sign-ins only, never an open session. It imports only `express` (for the type), `better-auth/node`, `./auth.js`, `../../../shared/context.js` and `../../../shared/errors.js` (the set-up test refuses logging, database, schema and repository imports in its code). A comment may explain the rule, but no file under `src/` other than `db/company.ts` may contain the text `app.company_id` (TASK-0016's test).
3. **Nothing else** reads or writes people in this card: the step reads only what Better Auth gives back (the person's ID, company and status, and the session's ID).

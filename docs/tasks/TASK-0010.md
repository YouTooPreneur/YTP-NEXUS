## STEPS
1. Edit `apps/api/package.json`: add `dependencies` `"pino": "10.4.0"` and `"pino-http": "11.0.0"` (exact). Run `pnpm install`.
2. Create `apps/api/src/shared/context.ts`:
   - `export interface RequestContext { requestId: string; background: boolean; userId?: string; companyId?: string }`
   - one module-level `AsyncLocalStorage<RequestContext>`;
   - `export function contextMiddleware(): RequestHandler` — for every request makes a context with `requestId` = `crypto.randomUUID()` and `background` = (the header `x-nexus-background` equals `'1'`), sets the answer header `x-request-id` to the request ID, and runs the rest of the request inside the storage;
   - `export function getContext(): RequestContext` — the current context; throws `Error('No request context')` outside a request;
   - `export function runWithContext<T>(context: RequestContext, fn: () => T): T` (for the worker and tests).
3. Create `apps/api/src/shared/logging.ts`:
   - `export const REDACT_PATHS = ['req.headers.cookie', 'req.headers.authorization', 'res.headers["set-cookie"]', '*.password', '*.code', '*.token', '*.secret', '*.newPassword', '*.currentPassword']` (`*.code` also hides the `code` field of logged errors, such as `EADDRINUSE`; the message text still names it. This is on purpose: two-step codes must never reach a log.)
   - `export function createLogger(destination?: pino.DestinationStream): pino.Logger` — `pino({ level: process.env.LOG_LEVEL ?? 'info', redact: { paths: REDACT_PATHS, censor: '[removed]' } }, destination)`.
   - `export function httpLogger(logger: pino.Logger): RequestHandler` — `pino-http` with that `logger`, and `genReqId` returning the context's `requestId`.
4. Create `apps/api/src/shared/errors.ts`:
   - `export class AppError extends Error` with `constructor(public readonly status: number, public readonly code: string, message: string, public readonly fields?: Record<string, string>)`.
   - `export function notFoundHandler(): RequestHandler` — passes `new AppError(404, 'not_found', 'Not found')` on.
   - `export function errorHandler(logger: pino.Logger): ErrorRequestHandler` — for an `AppError`, answers its `status` with `{ "error": { "code", "message", "fields" (only when given), "requestId" } }`; for an error from the body reader (it has `expose === true` and a `status` from 400 to 499), answers that status with code `too_large` and message `This is too large` when the status is 413, otherwise code `invalid_input` and message `Please check the form`, logged at level `warn` and never with the body; for anything else, logs the error with the request ID at level `error` and answers 500 with `{ "error": { "code": "server_error", "message": "Something went wrong. Please try again.", "requestId" } }`. The answer never contains a stack trace.
     It returns a function with Express's four parameters, `(error, req, res, next)`: Express 5 treats a function as an error handler only when it has all four. Its first lines are `if (res.headersSent) { next(error); return; }`, which hands an error that comes after the answer has started to Express's own handler. Do not rename the parameter to `_next` and do not add `eslint-disable` comments: lint refuses an unused `next` or `_next` (found in the review of TASK-0008, CR-008).
5. Edit `apps/api/src/app.ts`: `export interface AppOptions { logger?: pino.Logger; routes?: (app: Express) => void }` and `export function createApp(options: AppOptions = {}): Express`. In this order: `app.set('trust proxy', 1)`; `app.disable('x-powered-by')`; `contextMiddleware()`; `express.json({ limit: '1mb' })`; `httpLogger(options.logger ?? createLogger())`; the health door; `options.routes?.(app)`; `notFoundHandler()`; `errorHandler(logger)`. (`routes` lets tests add test doors; later cards mount real routes the same way.)
6. Replace `apps/api/src/main.ts` with exactly this. It logs `api listening` only when the port really works; when the port cannot be used (for example it is already taken), Express 5 passes the error to the same callback, so the API logs `api could not start` at level `error` and stops with exit code 1. An empty or non-numeric `PORT` falls back to 3000:
   ```ts
   import { createApp } from './app.js';
   import { createLogger } from './shared/logging.js';

   const logger = createLogger();
   const port = Number(process.env.PORT) || 3000;

   createApp({ logger }).listen(port, (error?: Error) => {
     if (error) {
       logger.error({ err: error, port }, 'api could not start');
       process.exit(1);
     }
     logger.info({ port }, 'api listening');
   });
   ```

# TASK-0097 · The job queue's pg-boss: errors logged, nothing made at run time, upkeep in the worker only

**Chain:** step 2.2 (database), follow-up of TASK-0021 · **Release:** 1 · **Module:** Core · **Part:** Backend (no door, no database change) · **Depends on:** TASK-0021 (Done) · **Lane:** fast (no screen, no door; one small file) · **Card style:** fast (D-202): the exact code below and the planner's tests
**Requirement IDs covered:** NFR-003 (the worker keeps running), TECH-DESIGN 5.2 (pg-boss in the worker)
**Builder:** Codex · **Reviewer:** Claude (planning session)

**Goal:** TASK-0021's job queue works, but its review found three things to put right before any card sends a job:
1. pg-boss reports its own problems (a lost database connection, a failed poll) as an `error` event, and nothing listens for it, so a database restart would stop the whole worker (and the API, once it sends jobs).
2. pg-boss's scheduler is on, so at every start it makes a queue of its own (`__pgboss__send-it`); the app must never make anything at run time.
3. The API would also do pg-boss's upkeep (its timers and clean-up) the first time it sends a job; only the worker should.

## RULES FOR THE CODE YOU WRITE
1. pg-boss is made in one place, once per process: by `startJobs` in the worker, which does pg-boss's upkeep (`supervise: true`), or by `sendJob` when no pg-boss has been made yet (the API: `supervise: false`, it only sends); after that, both use the one already made until `stop()` ends it, as now.
2. It never installs or changes its schema (`migrate: false`, as now) and makes nothing at run time: its scheduler is off (`schedule: false`). A card that adds a timed job first makes the scheduler's queue with a database change.
3. Right after it is made, before it starts, it gets one `error` listener that logs `job queue error` at level error and never throws: with `startJobs`'s logger when `startJobs` made it, otherwise with one logger of the jobs file's own, made once with `createLogger()`.
4. Nothing else changes: `JOB_POOL_SIZE`, `defineJob`, `sendJob`'s refusal and its message, each job's context and transaction, the failure handling and `stop()`.

     ```ts
     let bossInstance: PgBoss | undefined;
     let startPromise: Promise<PgBoss> | undefined;
     let ownLogger: pino.Logger | undefined;

     // pg-boss is made once per process: by startJobs in the worker, which does pg-boss's upkeep, or by sendJob in the
     // API, which only sends. It never installs or changes its schema and makes nothing at run time (no scheduler), and
     // its own errors (a lost connection, a failed poll) are logged and never stop the process (TASK-0097).
     function getOrCreateBoss(supervise: boolean, logger?: pino.Logger): PgBoss {
       if (!bossInstance) {
         const log = logger ?? (ownLogger ??= createLogger());
         bossInstance = new PgBoss({
           connectionString: process.env.DATABASE_URL_APP,
           schema: 'pgboss',
           max: JOB_POOL_SIZE,
           migrate: false,
           schedule: false,
           supervise,
         });
         bossInstance.on('error', (error: unknown) => log.error({ err: error }, 'job queue error'));
       }
       return bossInstance;
     }

     async function getBoss(supervise: boolean, logger?: pino.Logger): Promise<PgBoss> {
       const instance = getOrCreateBoss(supervise, logger);
       if (!startPromise) {
         startPromise = instance.start();
       }
       await startPromise;
       return instance;
     }
     ```

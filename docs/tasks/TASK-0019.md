**Chain:** DATABASE (step 13 of 17) · **Release:** 1 · **Module:** Core · **Part:** Backend (D-187; a shared backend card with no door, AGENTS.md section 7) · **Depends on:** TASK-0018 · **Lane:** careful (it changes the error handler every request goes through and adds database changes, so no other database card is built at the same time, CR-022)
**Requirement IDs covered:** CORE-140 (recent errors for Monitoring), NFR-012 (errors kept for the monitoring alerts), NFR-014 (a company never sees another company's errors or the rows with no company), DATA-MODEL 3.4 (`core.error_events`), TECH-DESIGN 5.1 and 5.2 (rows with no company, `nexus_system`'s functions) and section 7 (no secret kept outside the log)
**Builder:** Antigravity (D-201) · **Reviewer:** Claude (planning session)

**Goal:** the thirteenth card of step 2.2. Every **server error** (an unexpected error in a door, or an `AppError` of 500 or more, such as an outside service that is down) is now **kept for Monitoring** in a new table, `core.error_events`: under the company of the request that met it, or with **no company** (a system error) when the request has none. The error handler keeps it **without making the answer wait**: the person still gets the same answer at once, and if the error cannot be kept (the database is down), that is only logged as a warning. Only the **cleaned message** is kept, never a failed query's values or anything secret: a new helper, `safeErrorMessage`, gives the same cleaned message the log gets, and every later column that keeps an error's text uses it. Errors are added only through one database function, `core.record_error`, owned by the system account, in a short write of their own, so an error stays even when the request's own work is undone. Answers under 500 (a wrong form, a page not found, a stale save) are never kept. Two readers give the **rows with no company** to the platform operator's doors (built later): `core.system_errors` (the newest system errors) and `core.system_security_entries` (the security log's system chain, newest first); both refuse once Nexus has a second company, until the platform operator is settled. The app reads its own company's errors with an ordinary query.

   ```ts
// An error's message for a column kept outside the log (core.error_events now; later the outbox, the doors and failed
// jobs; TECH-DESIGN section 7): the same cleaned message the log gets, without a failed query's values; an error with
// no message gives its type, and anything thrown that is not an error gives only what kind of value it is. Never
// error.message, String(error), the stack or the whole error.
export function safeErrorMessage(value: unknown): string {
  const error = isErrorLike(value) && value.raw instanceof Error ? value.raw : value;
  if (!isErrorLike(error)) return typeof error;
  const described = describeError(error);
  return described.message || described.type;
}
   ```

   ```ts
import { sql } from 'drizzle-orm';
import type { Transaction } from '../../../db/company.js';
import { securityWrite, securityWriteWithoutCompany } from '../../../db/database.js';
import { getContext, type RequestContext } from '../../../shared/context.js';
import { safeErrorMessage } from '../../../shared/logging.js';

// The error recorder (TASK-0019, CORE-140). It adds an error to core.error_events through the database function
// core.record_error, in a short security write of its own, so the error stays when the request's or job's own
// transaction is undone: under the context's company, or with no company (a system error) when there is none. Only the
// cleaned message is kept (safeErrorMessage, never the error itself), with the request's or job's ID.
export type ErrorSource = 'api' | 'worker';

// The request or job context, or none outside one (a command-line script, a test).
function currentContext(): RequestContext | undefined {
  try {
    return getContext();
  } catch {
    return undefined;
  }
}

export async function recordError(error: unknown, source: ErrorSource): Promise<string> {
  const context = currentContext();
  const message = safeErrorMessage(error);
  const requestId = context?.requestId ?? null;
  const add = async (tx: Transaction): Promise<string> => {
    const result = await tx.execute(
      sql`SELECT core.record_error(${source}, ${message}, ${requestId}) AS id`,
    );
    const id = result.rows[0]?.id;
    if (typeof id !== 'string') {
      throw new Error('the error was not recorded');
    }
    return id;
  };
  return context?.companyId
    ? securityWrite(context.companyId, add)
    : securityWriteWithoutCompany(add);
}
   ```
4. Replace the whole content of `apps/api/src/shared/errors.ts` with exactly this (it imports `recordError`, adds `keepError`, logs and keeps an `AppError` of 500 or more, and keeps an unexpected error; everything else stays as it is):
   ```ts
import type { ErrorRequestHandler, RequestHandler } from 'express';
import type { pino } from 'pino';
import { getContext } from './context.js';
import { recordError } from '../modules/core/repository/error-events.js';

export class AppError extends Error {
  constructor(
    public readonly status: number,
    public readonly code: string,
    message: string,
    public readonly fields?: Record<string, string>,
  ) {
    super(message);
    this.name = 'AppError';
  }
}

export function notFoundHandler(): RequestHandler {
  return (_req, _res, next) => {
    next(new AppError(404, 'not_found', 'Not found'));
  };
}

// Keeps a server error for Monitoring (TASK-0019) without making the answer wait for it; a failure to keep it is
// logged as a warning, never thrown.
function keepError(logger: pino.Logger, error: unknown, requestId: string): void {
  recordError(error, 'api').catch((failure: unknown) => {
    logger.warn({ err: failure, requestId }, 'error not recorded');
  });
}

export function errorHandler(logger: pino.Logger): ErrorRequestHandler {
  return (error, req, res, next) => {
    if (res.headersSent) {
      next(error);
      return;
    }

    const requestId = getContext().requestId;

    if (error instanceof AppError) {
      // An AppError of 500 or more (an outside service that is down, for example) is a server error: logged and kept
      // like an unexpected one, then answered with its own status and format.
      if (error.status >= 500) {
        logger.error({ err: error, requestId }, 'server error');
        keepError(logger, error, requestId);
      }
      const errorBody: {
        code: string;
        message: string;
        requestId: string;
        fields?: Record<string, string>;
      } = {
        code: error.code,
        message: error.message,
        requestId,
      };
      if (error.fields !== undefined) {
        errorBody.fields = error.fields;
      }
      res.status(error.status).json({ error: errorBody });
      return;
    }

    const isBodyError =
      typeof error === 'object' &&
      error !== null &&
      'expose' in error &&
      (error as { expose?: unknown }).expose === true &&
      typeof (error as { status?: unknown }).status === 'number' &&
      (error as { status: number }).status >= 400 &&
      (error as { status: number }).status <= 499;

    if (isBodyError) {
      const bodyError = error as { status: number; type?: string };
      logger.warn(
        { requestId, status: bodyError.status, type: bodyError.type },
        'request body refused',
      );
      const code = bodyError.status === 413 ? 'too_large' : 'invalid_input';
      const message = bodyError.status === 413 ? 'This is too large' : 'Please check the form';
      res.status(bodyError.status).json({
        error: {
          code,
          message,
          requestId,
        },
      });
      return;
    }

    logger.error({ err: error, requestId }, 'server error');
    keepError(logger, error, requestId);
    res.status(500).json({
      error: {
        code: 'server_error',
        message: 'Something went wrong. Please try again.',
        requestId,
      },
    });
  };
}
   ```

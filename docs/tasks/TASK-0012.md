## STEPS
1. Create `apps/api/src/announcements.ts`: `export interface AnnouncementInfo { name: string; module: string }` and `export const allAnnouncements: AnnouncementInfo[] = [];` (the cards that add announcements add them here).
2. Create `apps/api/scripts/list-routes.ts`: imports `allRoutes` from `../src/routes.js` and `allAnnouncements` from `../src/announcements.js`, and prints one JSON object: `{ "routes": [ { operationId, method, path, module, public, permission, feature } … ], "authRoutes": [], "announcements": [ { name, module } … ] }` (`permission` and `feature` are `null` for public doors). `authRoutes` stays an empty list until TASK-0032 fills it with the open Better Auth routes as `"<METHOD> <path>"` strings.
3. Edit `apps/api/package.json` `scripts`: add `"routes:list": "tsx scripts/list-routes.ts"`.
4. Create `tools/verify/auth-routes.json` (the agreed open sign-in doors, TECH-DESIGN 6.1):
   ```json
   [
     "POST /api/auth/sign-in/email",
     "POST /api/auth/sign-in/social",
     "GET /api/auth/callback/google",
     "POST /api/auth/sign-out",
     "GET /api/auth/get-session",
     "POST /api/auth/request-password-reset",
     "POST /api/auth/reset-password"
   ]
   ```
5. Create `tools/verify/checks/contract.mjs` exporting `compareRoutesToContracts(routes, openapi)` → a sorted list of problems: `route without contract: <method> <path> <operationId>` and `contract without route: <method> <path> <operationId>`, comparing the routes with every method under every path of the OpenAPI document (method in lower case, path exactly as written).
6. Create `tools/verify/checks/doors.mjs` exporting `checkDoors({ routes, authRoutes, allowedAuthRoutes })` → a sorted list of problems: `door without permission or feature: <operationId>` for a non-public route missing either; and, **only when `authRoutes` is not empty**, `sign-in door not on the list: <route>` and `sign-in door on the list but missing: <route>`.
7. Create `tools/verify/checks/module-cards.mjs` exporting:
   - `SECTIONS = ['## Data', '## Rules', '## Screens', '## Window', '## Announcements', '## Night checklist']`;
   - `checkModuleCards({ modules, routes, announcements })`, where `modules` is a list of `{ name, card }` (`card` is the MODULE.md text or `null`) → a sorted list of problems: `module <name> has no MODULE.md`; `MODULE.md of <name> is missing the section <section>`; `<operationId> is not listed under Window in <module>/MODULE.md`; `<name> is not listed under Announcements in <module>/MODULE.md`. "Listed" means the name appears in backticks between that section's heading and the next `## ` heading.
8. Create `apps/api/src/modules/core/MODULE.md` from `docs/templates/MODULE-CARD.md`: name "Core", floor "ground", schema `core` (and `audit`), first release 1; **Data** "(tables come with step 2.2)"; **Rules** "Core serves everyone and asks no module (D-014)" and "Core's sign-in code lives in `modules/core/signin/` and its users code in `modules/core/users/`; only these two folders and `src/db/` may touch the `auth` schema (the auth-schema wall, TECH-DESIGN 5.1)"; **Screens** "(Release 1 screens come with steps 2.4 to 2.7)"; **Window** one line: `` `getHealth`: GET /api/health, public, no feature key ``; **Announcements** "(none yet)"; **Night checklist** "(none yet)".
9. Edit `tools/verify/steps.mjs`: directly after `Architecture`, add `Contract`, `Doors` and `Module cards`, in that order. They share one run of `pnpm --filter @ytp/api --silent routes:list` (parse its JSON), made inside the first of the three steps' `run` and kept on `ctx` for the other two, never when `steps.mjs` is loaded (a failure then counts as a failed step instead of stopping verify) and read `packages/contracts/openapi.json` and `tools/verify/auth-routes.json`; the module list is every folder under `apps/api/src/modules/` with its `MODULE.md` (or `null`). Each fails with its problems as the note. `Allowed files` stays the last step.
10. Edit `tools/verify/checks/allowed-files.mjs` (Node built-ins only; run git as the rest of the file does: in `root`, an argument list, no shell, arguments starting with `-c core.quotepath=off`):
    - In `changedFiles`, the fallback `git diff` becomes `git diff --name-only --no-renames <startCommit>`. Change nothing else in that function. (Why: `git diff` treats a moved file as one rename and lists only its new path, so moving a file that is not allowed to an allowed path passed the check before the commit.)
    - Add and export `commitProblems(root, startCommit)` → a list of problem strings, oldest commit first, empty when all is well: for every commit listed by `git log --no-merges --reverse --format=%h%x09%s <startCommit>..HEAD --not main` whose subject does not start with a card ID and a colon (`/^TASK-\d{4}:/`), the string `commit not named for a card: <short hash> <subject>`. Leave out `--not main` when the folder has no `main` branch (`git rev-parse --verify --quiet refs/heads/main` fails). (Why: once a card is committed, the check reads only the commits named for it, so a second commit with another name, such as `tidy up`, was checked by nobody but would reach `main` with the merge. Commits already on `main`, such as the planner's, are not the card's.)
11. Edit `tools/verify/steps.mjs`, step `Allowed files`: after `checkAllowedFiles`, also call `commitProblems(ctx.root, <start point>)`. The step fails when either list is not empty; its note is `not allowed: <paths, comma-separated>` (only when there are such paths) followed by the commit problems, all joined with `; `. Without `--card` nothing changes.

## STEPS
1. Create `tools/verify/lib.mjs` (plain JavaScript, Node built-ins only) exporting:
   - `readLock(text)` → an array of `{ card, path, sha256 }`. Skip empty lines and lines starting with `#`. Each other line is three parts separated by spaces: a card ID matching `^TASK-\d{4}$`, a path (forward slashes), and a 64-character lower-case hex fingerprint. Any other line throws `Error('tests/LOCK line <n>: <the line>')` (n counts from 1).
   - `readIndexStatuses(markdown)` → a `Map` from card ID to its status text, read from the first table in `docs/tasks/INDEX.md` whose header row contains a cell `Task` and a cell `Status` (use the header to find the Status column; do not assume its position). Status text is trimmed.
   - `listTestFiles(root)` → every file, as a path relative to `root` with forward slashes, matching: `tests/setup/*.test.mjs`, `apps/*/test/**/*.test.ts`, `apps/*/test/**/*.test.tsx`, `packages/*/test/**/*.test.ts`, `packages/*/test/**/*.test.tsx`. Never anything under `node_modules` or `tests/setup/fixtures`. Sorted.
   - `selectTests({ files, lock, statuses, card })` → `{ run, left }` (both sorted). A file listed in the lock runs when its card's status is `Done` or its card is `card`; otherwise it is in `left`. A file not listed in the lock (a builder's own test) always runs.
   - `packageOf(path)` → for `apps/<x>/…` or `packages/<x>/…` the folder `apps/<x>` or `packages/<x>`; for anything else `null`.
2. Create `tools/verify/steps.mjs` exporting `steps`: an array of `{ name, run(ctx) }`, run in this order. `ctx` holds `root`, `card` (or `null`) and `selected` (the `run` list from `selectTests`). Each `run` returns `{ ok: boolean, note?: string }`; each runs commands with `child_process.spawnSync` (shell on, output shown live) from `root`.
   1. **`API client`** — `pnpm api:generate`.
   2. **`Type check`** — for each folder under `apps/` and `packages/` that has a `tsconfig.json`: write `<folder>/tsconfig.verify.json` as `{ "extends": "./tsconfig.json", "include": [<that tsconfig's own include list>, <the selected test files of that folder, relative to it>] }`, then run `pnpm --filter <name> exec tsc -p tsconfig.verify.json --noEmit`. So the tests of cards not yet Done are never type-checked, and the ones that run always are.
   3. **`Set-up tests`** — `node --test` with the selected files under `tests/setup/`; if there are none, `{ ok: true, note: 'no set-up tests to run' }`.
   4. **`Unit and API tests`** — group the selected files whose `packageOf` is not `null` (those under `apps/` or `packages/`) by `packageOf`; for each package, read its `package.json` name and run `pnpm --filter <name> exec vitest run <files, relative to the package folder>`. All groups must pass; with no files, `{ ok: true, note: 'no unit tests to run' }`.
3. Create `tools/verify/verify.mjs` (the command):
   - Arguments: `--card TASK-XXXX` and `--list`. A `--card` value that does not match `^TASK-\d{4}$`, or whose `docs/tasks/TASK-XXXX.md` does not exist, prints `verify: unknown card <value>` and exits with code 2. Any other argument prints `verify: unknown argument <value>` and exits with code 2.
   - `--list` prints each step name on its own line, in order, and exits 0.
   - Otherwise: read `tests/LOCK` and `docs/tasks/INDEX.md`, list the test files, select them, print `verify: running <n> test files, leaving out <m> (cards not Done)`, then run every step in order (all of them, even after a failure), printing `▶ <name>` before and `✔ <name>` or `✖ <name>` after (plus the note, if any).
   - It ends with `verify: PASSED` (exit 0) or `verify: FAILED: <failed step names, comma-separated>` (exit 1).
4. Edit the root `package.json` `scripts`: add `"verify": "node tools/verify/verify.mjs"`.
5. Run `pnpm verify` (all Done cards' tests run) and `pnpm verify --card TASK-0007` (the same plus this card's test).

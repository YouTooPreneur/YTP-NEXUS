**Builder:** Claude (a building session, D-202) · **Reviewer:** Claude (planning session)

**Goal:** the third and fourth shared steps that every door with a permission runs. **The permission check** (`checkPermission`, Core's one check, D-019): after the feature switch, it reads the person's role from `core.users` in the request's own transaction and the role's grant for the door's permission, and puts `access` on the request context: the grant's **scope** (own, team or all) and **every field the role does not see**, in every module. A person missing in the company, deleted or purged gets 401 `not_signed_in`; no grant for the door, or a deleted role, gets 403 `not_allowed`. The Owner has no way around its own grants. **Hiding** (`hideFields`): after the answer is checked, it removes those fields from the answer at the paths the door's contract names, in a copy, so the double-click step's kept answer stays whole and is hidden again when replayed. **Contracts** name their hideable fields as a map from answer path to hidden name, and a checker makes sure each such field is `.optional()` in the answer, so the screens never count on it. Every door's repository reads the scope with `currentAccess()`, Core's Release 1 doors included, and none reads own or team as all (those doors come with later cards).

## RULES FOR THE CODE YOU WRITE
1. **The check** (`modules/core/service/access.ts`, Core's one permission check, D-019):
   - `export async function accessFor(permission: { module: string; action: string }): Promise<Access> {`. It needs the request transaction, the company and the person on the request context (`getContext()`: `tx`, `companyId`, `userId`); without any of them it throws `new Error('the permission check needs the request transaction and the person')` (a plain error: 500).
   - It reads, on `tx` only, with its own `forCompany(<table>.companyId, companyId)` on each of the four company tables it reads (`users`, `roles`, `rolePermissions` and `roleHiddenFields`, even where a join already matches the company): the person's `core.users` row by `userId`, with no `deleted_at` and no `purged_at`, and their role in the same company (`core.roles` by `(company_id, role_id)`); the role's `core.role_permissions` row for exactly the permission's `module` and `action`; and every `core.role_hidden_fields.field` of the role, **in every module**. No person row: `new AppError(401, 'not_signed_in', 'Please sign in.')`. A deleted role (`core.roles.deleted_at` set) or no grant: `new AppError(403, 'not_allowed', 'You are not allowed to do this.')`. Otherwise it gives back `{ scope, hiddenFields }` with the grant's scope and the hidden field names distinct and sorted with JavaScript's `.sort()` (never left to the database's order or collation).
   - It takes no lock (no `.for(...)`, no `FOR UPDATE` or `FOR SHARE`, no advisory lock), opens no transaction of its own, writes nothing, logs nothing and caches nothing: a change to a grant, a hidden field or the person's row applies to the very next request. A database failure goes through as it is (a plain error: 500), never turned into a 401 or 403. The Owner has no special path: it passes through its own grants like any role.
   - `export async function checkPermission(info: RouteInfo): Promise<void> {`: when `info.route.permission` is missing it throws `` new Error(`${info.route.operationId}: the permission step needs the door's permission`) ``; otherwise it sets `getContext().access` to `await accessFor(info.route.permission)`, on the request's own context (never `runWithContext`).
   - `export function currentAccess(): Access {`: gives back `getContext().access`, or throws `new Error('the scope needs the permission step')` when it is missing, so a repository never reads a missing scope as "all".
   - Imports only: `drizzle-orm` (its query helpers), `../../../db/company.js` (`forCompany`), `../../../shared/context.js` (`getContext`, `type Access`), `../../../shared/errors.js` (`AppError`), `type RouteInfo` from `../../../shared/route.js`, `../schema/roles.js` and `../schema/users.js`.
   - Neither new file in `apps/api/src` names `app.company_id`, `auth.user`, `auth.session`, `auth.account` or `auth.verification`, not even in a comment (`tests/setup/TASK-0016.test.mjs` and `TASK-0032.test.mjs` read the text).
2. **Hiding** (`src/shared/hide-fields.ts`): `export function hideFields(info: RouteInfo, answer: unknown): unknown {`, plain and synchronous (no `async`, no `await`, no Promise).
   - When the door's contract names no hideable field (`info.route.contract.hideableFields` missing or empty), it gives back `answer` itself and reads nothing, not even the request context.
   - Otherwise it reads `getContext().access`; when that is missing it throws `` new Error(`${info.route.operationId}: hidden fields need the permission step`) `` (a plain error: 500).
   - For each `[path, name]` of `hideableFields` whose `name` is in `access.hiddenFields`, it removes the field at `path` by deleting the key (never setting it to `undefined`). It works on a copy, copying only along the paths it changes: the given answer never changes (it may be the double-click step's kept answer).
   - A path has dots between keys; `key[]` means each item of the list at `key`; a path starting `[].` means each item of an answer that is a list; the last part is always a plain key. A part whose parent is missing, `null`, or not what the path expects (a plain object, not a list, for a key; a list for `[]`) is skipped, even when the key is there; list items that are not objects are left as they are.
3. **Contracts** (`packages/contracts`): `hideableFields` becomes a map from answer path to hidden field name (step 6). `export function hideableProblems(contract: Contract): string[] {` in `src/hideable.ts` gives back, entry by entry in the map's order, the first of the three path problems below that applies (if any) and then, separately, the name problem (if the name is wrong), so one entry can give two problems:
   - the path is not `^(\[\]\.)?([A-Za-z_][A-Za-z0-9_]*(\[\])?\.)*[A-Za-z_][A-Za-z0-9_]*$`: `` `${operationId}: ${path} is not a valid answer path` ``;
   - the path cannot be followed in `contract.response` (walking through `z.ZodOptional`, `z.ZodNullable` and `z.ZodReadonly` on the way, before a key, before `[]` and on a list's items; into a `z.ZodObject` by its own key; into a `z.ZodArray`'s element for `[]`; anything else, a union, a record or an object's catchall included, ends the walk): `` `${operationId}: ${path} is not in the answer` ``;
   - the field at the end is not a `z.ZodOptional` (`.optional()` or `.nullish()` written last; `.nullable()` alone, `.optional().nullable()`, `.exactOptional()`, `.default()` and `z.any()` are not): `` `${operationId}: ${path} must be .optional() in the answer` ``;
   - and the name is not `^[a-z][a-z0-9]*\.[a-z][a-z0-9_]*\.[a-z][A-Za-z0-9]*$` (`<module>.<record type>.<field>`, for example `finance.invoice.total`): `` `${operationId}: ${path} is hidden as ${name}, which is not <module>.<record type>.<field>` ``.
   It imports only `zod` and `./contract.js`.

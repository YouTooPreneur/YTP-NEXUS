# TASK-0093 · Activity-log writer: refuse a missing record ID, never store a secret

**Chain:** DATABASE (step 10 of 17) · **Release:** 1 · **Module:** Core · **Part:** Backend (D-187; a shared backend card with no door, AGENTS.md section 7) · **Depends on:** TASK-0022 · **Lane:** fast (no database change)
**Requirement IDs covered:** CORE-090 (activity log), RULE-025 (no stored passwords), NFR-001 (security); found by Codex's extra check of TASK-0017 (CR-024)
**Builder:** Claude, in its own building session (D-185, D-200) · **Reviewer:** a separate Claude checking session (D-200, `docs/templates/CHECK-PROMPT.md`)

**Goal:** Codex's independent check of TASK-0017 found two gaps in the activity-log writer `writeActivity`, both in the planner's card, not in the builder's work. First, a caller that leaves out the record ID got past the ID check and reached the database, which then refused it with its own error; the writer must refuse a missing or empty record ID itself, before the database sees it, with the same message as a wrong ID. Second, the writer stored every field of `changes` as given, so a caller's mistake could put a password, token or other secret into the log for good; the writer must never store one. A field whose name looks like a secret (it contains password, passcode, secret, token, API key or private key, in any spelling: `newPassword`, `client_secret`, `API-Key`, `gmail.app_password`) is kept as changed, so the history still shows that it changed, but both its values become `[hidden]`; a secret-looking part deeper inside a value is hidden too; everything else, `code` and `key` included, is kept as it is. This card replaces the writer's file with the corrected one.

1. Replace the whole content of `apps/api/src/modules/core/repository/activity-log.ts` with exactly this:
   ```ts
   import { getContext } from '../../../shared/context.js';
   import { activityLog } from '../schema/activity-log.js';

   // The activity-log writer (TASK-0017, CORE-090, TECH-DESIGN section 2 step 13): every save writes its entry in the
   // transaction on the request context, so the entry is kept or undone together with the change. The company and the
   // request ID come from the context, never from the entry, and the writer opens no transaction of its own. Work
   // outside a request (a job, a command, a test) runs inside runWithContext with its own requestId, companyId and tx.
   export type ActorType = 'automation' | 'api' | 'mcp' | 'ai' | 'system';

   export interface Actor {
     type: ActorType;
     label: string;
     userId?: string;
   }

   export interface ActivityEntry {
     module: string;
     recordType: string;
     recordId: string;
     recordLabel: string;
     action: string;
     changes?: Record<string, { old: unknown; new: unknown }>;
     clientId?: string;
     actor?: Actor;
   }

   const ID = /^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i;

   // An ID is checked before it reaches the database, so a wrong value never appears in a database error; a required
   // ID that is missing is refused the same way (TASK-0093).
   function checkId(value: string | undefined, required = false): void {
     if ((required || value !== undefined) && !ID.test(value ?? '')) {
       throw new Error('the activity entry holds an ID that is not valid');
     }
   }

   // A field whose name looks like a secret (a password, passcode, secret, token, API key or private key, in any
   // spelling) is never stored: a changed field keeps its name with both values hidden, and a deeper one is hidden
   // (TASK-0093, RULE-025).
   const HIDDEN = '[hidden]';
   const SECRET = /pass(word|code)|secret|token|apikey|privatekey/;

   function isSecret(name: string): boolean {
     return SECRET.test(name.toLowerCase().replace(/[^a-z]/g, ''));
   }

   export async function writeActivity(entry: ActivityEntry): Promise<string> {
     const context = getContext();
     if (!context.tx) {
       throw new Error('the activity log needs the transaction');
     }
     if (!context.companyId) {
       throw new Error('the activity log needs the company');
     }
     let who: { actorType: ActorType | 'person'; actorUserId?: string; actorLabel?: string };
     if (entry.actor) {
       who = {
         actorType: entry.actor.type,
         actorUserId: entry.actor.userId,
         actorLabel: entry.actor.label,
       };
     } else if (context.userId) {
       who = { actorType: 'person', actorUserId: context.userId };
     } else {
       throw new Error('the activity log needs who did it');
     }
     checkId(entry.recordId, true);
     checkId(entry.clientId);
     checkId(who.actorUserId);
     // A value left undefined is kept as null, so the entry still shows that the field changed.
     const kept = JSON.parse(
       JSON.stringify(entry.changes ?? {}, (key, value: unknown) =>
         key !== '' && isSecret(key) ? HIDDEN : value === undefined ? null : value,
       ),
     ) as Record<string, unknown>;
     const changes = Object.fromEntries(
       Object.entries(kept).map(([field, change]) => [
         field,
         isSecret(field) ? { old: HIDDEN, new: HIDDEN } : change,
       ]),
     );
     const [row] = await context.tx
       .insert(activityLog)
       .values({
         companyId: context.companyId,
         ...who,
         module: entry.module,
         recordType: entry.recordType,
         recordId: entry.recordId,
         recordLabel: entry.recordLabel,
         action: entry.action,
         changes,
         clientId: entry.clientId,
         requestId: context.requestId,
       })
       .returning({ id: activityLog.id });
     if (!row) {
       throw new Error('the activity entry was not saved');
     }
     return row.id;
   }
   ```

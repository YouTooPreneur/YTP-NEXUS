**Goal:** two changes to the door helper every API door uses. (1) **Every answer is checked against its contract** before it leaves: fields the contract does not declare are dropped (so a database row's extra columns, such as a scrambled password, never leave), and an answer of the wrong shape becomes a plain 500 with nothing saved, logged only with the door's name. For a non-public door the check runs inside the double-click step, so the stored first answer is the checked one. (2) A third kind of door, **signed in only**: it has a feature key but no permission, and runs every shared step except the permission check (for your own profile, your devices, sign-out, "who am I" and the two-step doors). The routes listing marks such doors and the verify door check accepts them. The permission check itself and hidden fields come with TASK-0031.

## RULES FOR THE CODE YOU WRITE
1. **Kinds of door** (`route.ts`): a route definition is public (`public: true`, no permission or feature), signed in only (`signedIn: true` and a `feature`, no permission) or guarded (a `permission` and a `feature`). `defineRoute` reads the kind with `def.public === true`, `def.signedIn === true`, `def.permission` and `def.feature`, with no `as` casts and no `!` anywhere in `route.ts`. It refuses, with these exact messages: `Route <operationId> cannot be both public and signed in only`; `Route <operationId> is signed in only and cannot declare a permission`; `Route <operationId> is signed in only and must declare its feature key`; and the two existing messages unchanged. A registered signed-in route carries `signedIn: true`; no other route has a `signedIn` key at all.
2. **The answer check:** `checkAnswer(route, answer)` runs `route.contract.response.safeParse(answer)` and gives back its data, or throws `new Error(`${route.operationId}: the answer does not match its contract`)` with no `cause` (a checker's message is never logged). A public door checks the answer before sending it; a non-public door runs `h.idempotency(info, async () => checkAnswer(route, await route.handler(input, info)))`, then `hideFields` on the checked answer, as today.
3. **Signed-in doors** run every shared step in the same order as guarded doors except `permission`.
4. **The routes listing** (`list-routes.ts`) adds `...(r.signedIn ? { signedIn: true } : {})` to each route's entry (written exactly so); every other key stays as it is, so the health door's entry is unchanged.
5. **The door check** (`doors.mjs`): a non-public door is right when it has a feature key and either a permission or `signedIn: true`; otherwise it is still reported as `door without permission or feature: <operationId>`.

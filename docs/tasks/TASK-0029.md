**Goal:** every outside service Nexus uses connects through a **door** in Core (D-018). In this card a door is a connection to an outside service (TECH-DESIGN 6.4), never an API door: nothing here is an HTTP route, and nothing goes under `## Window`. Release 1 has two doors: `email` (Gmail online; an SMTP server such as Mailpit in development and tests; TASK-0099) and `files` (Cloudflare R2 online, SeaweedFS in development; TASK-0069). This card builds what every door shares:
1. **The table** `core.doors`: one row per company and door, with its provider, its status (`not_connected`, `connected` or `error`), an on/off switch, non-secret settings and its last check (when, whether it passed, and the cleaned error). It never holds a key or password: in Release 1 keys come from the environment file (TECH-DESIGN 6.4 and 6.6).
2. **The writer** `recordDoorCheck`: each door calls it after a health check or a send to record the result, in a security write of its own, so the result is kept even when the caller's own transaction is undone. It is the only code that adds or changes rows of `core.doors`. Monitoring (TASK-0058) reads the table later.

   - **First the refusals**, before any database work: a `check.key` not in `DOOR_KEYS` throws exactly `new Error('recordDoorCheck: unknown door')`; then a `check.provider` not in `DOOR_PROVIDERS` throws exactly `new Error('recordDoorCheck: unknown provider')` (plain errors; the message never repeats the value given).

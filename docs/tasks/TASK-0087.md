**Goal:** close the last gap found in the review of TASK-0086 (CR-011). When an error is logged without a message (`logger.error(err)` or `logger.error({ err })`), pino writes the error's own message as the line's `msg` before any printer runs, so a failed database query's values reached the log there even though `err` itself was cleaned. From now on such a line gets the cleaned message; a line that has a message keeps it exactly as before (TECH-DESIGN section 7).

## STEPS
1. In `apps/api/src/shared/logging.ts`, inside `createLogger`'s options, directly after the line `serializers: { err: cleanError },` and before `formatters: {`, add exactly this. Change nothing else.
   ```ts
         hooks: {
           // With no message, pino writes the error's own message as `msg` before any printer runs,
           // a failed query's values included; this hands it the cleaned message instead.
           logMethod(args, method) {
             const [first, second] = args as unknown[];
             const object = (typeof first === 'object' && first !== null ? first : {}) as {
               err?: unknown;
               msg?: unknown;
             };
             const error =
               first instanceof Error ? first : object.msg === undefined ? object.err : undefined;
             if (second === undefined && isErrorLike(error)) {
               return method.apply(this, [first, describeError(error).message] as never);
             }
             return method.apply(this, args);
           },
         },
   ```
   Why: pino copies the error's message into `msg` only when the call has no message and the object has no `msg`; this does the same with the cleaned message, so every other call is left exactly as it was. Child loggers, the request logger (`req.log`) included, use the same hook.

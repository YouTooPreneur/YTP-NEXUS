# TASK-0085 · Screens' API client: background and double-click headers

**Chain:** SCREENS (step 1) · **Release:** 1 · **Module:** Core · **Part:** Frontend (D-187) · **Depends on:** TASK-0088 · **Lane:** fast (no database change, so it may be built while a database card is built elsewhere, D-201)
**Requirement IDs covered:** CORE-003 (background refreshes do not keep a session alive), NFR-021 (a double click never does a thing twice), TECH-DESIGN section 2 (step 6), 6.7 ("Double clicks") and section 12 point 57
**Builder:** Codex (D-201) · **Reviewer:** Claude (planning session)

**Goal:** the screens' generated API client (Orval, `apps/web/src/api/`, made fresh on every run) gets the screens' own fetch, `nexusFetch`, in a new file outside the generated folder. Every request from the screens goes through it. Every change (POST, PUT, PATCH, DELETE) carries an `Idempotency-Key`: the key the screen passes when it sends the same change again (a second click, "Try again"), otherwise a new UUID; a read never carries one. A request the screen marks as background (`{ background: true }`, for an automatic refresh) carries `X-Nexus-Background: 1`, so the backend does not count it as the person's activity. Every answer that is not a success, and a success that is not JSON (a page instead of the API), becomes an Error with its `status` and, for a JSON answer, its body as `info`; the message never holds the answer's text. A success gives `{ data, status, headers }`. The query library's own retries and refetches (on window focus, on reconnect) are switched off for every generated query, because they could not be marked as background; a screen that needs fresh data refreshes on a timer and marks it background. Finally the screens' last two lint rules left at warning level are settled: unsupported syntax (such as `eval`) becomes an error, and the form-library warning is switched off (TECH-DESIGN section 12 point 57).

## STEPS
1. Create the folder `apps/web/src/requests/` and in it `nexus-fetch.ts` with exactly this content:
   ```ts
   // The screens' own fetch for the generated API client (TASK-0085, TECH-DESIGN section 2 step 6 and 6.7). Orval's
   // client calls it for every door. Every change carries a double-click key: the one the screen passes when it sends the
   // same change again, otherwise a new one; a read never carries one. A request the screen marks as background (an
   // automatic refresh) carries X-Nexus-Background: 1, so it does not keep a session alive. Every answer that is not a
   // success becomes an Error with its status. The browser sets Origin and Sec-Fetch-Site itself; this fetch never does.
   export type NexusRequestInit = RequestInit & { background?: boolean; idempotencyKey?: string };

   export type ErrorType<Info> = Error & { info?: Info; status?: number };

   const CHANGES = new Set(['POST', 'PUT', 'PATCH', 'DELETE']);
   const NO_BODY = new Set([204, 205, 304]);

   export const nexusFetch = async <T>(url: string, init: NexusRequestInit = {}): Promise<T> => {
     const { background, idempotencyKey, ...rest } = init;
     const method = (rest.method ?? 'GET').toUpperCase();
     const headers = new Headers(rest.headers);
     headers.delete('Idempotency-Key');
     headers.delete('X-Nexus-Background');
     if (CHANGES.has(method)) {
       headers.set('Idempotency-Key', idempotencyKey ?? crypto.randomUUID());
     }
     if (background === true) {
       headers.set('X-Nexus-Background', '1');
     }
     const res = await fetch(url, { ...rest, method, headers });
     const text = NO_BODY.has(res.status) ? '' : await res.text();
     let body: unknown;
     let json = false;
     if (text !== '' && (res.headers.get('content-type') ?? '').includes('json')) {
       try {
         body = JSON.parse(text);
         json = true;
       } catch {
         body = undefined;
       }
     }
     // An answer that is not a success, or a success that is not JSON (a page instead of the API), is refused with its
     // status; the message never holds the answer's text.
     if (!res.ok || (text !== '' && !json)) {
       throw Object.assign(new Error(`The API answered ${res.status}`), {
         status: res.status,
         info: body,
       });
     }
     return { data: body, status: res.status, headers: res.headers } as T;
   };
   ```

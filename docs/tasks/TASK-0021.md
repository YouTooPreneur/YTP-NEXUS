**Builder:** Antigravity (D-202) · **Reviewer:** Claude (planning session)

**Goal:** the worker gets a **job queue** (pg-boss, pinned `12.38.0`) for work that runs later or on a schedule (emails, reminders, nightly checks in later cards). A job is defined once with `defineJob`, sent with `sendJob` (which keeps the company of the request that sent it), and run once by the worker in a fresh background context and a transaction of that company only, so a job can never see or change another company's data. A failed job is logged, kept as an error under its company, retried as its definition says, and only its cleaned message is stored. The `pgboss` schema and every queue are made by database changes as `nexus_owner`; the app's account only uses them. No real job exists yet: the first cards that need one (the email door, TASK-0029) add theirs.

## RULES FOR THE CODE YOU WRITE
1. **Package:** `pnpm --filter @ytp/api add pg-boss@12.38.0 --save-exact`. No other new package. Only files in `src/jobs/` import `pg-boss`.
2. **The schema change:** run `pnpm --filter @ytp/api db:generate --custom --name pgboss_schema` and fill the new file with pg-boss 12.38.0's own SQL that installs its schema named `pgboss` (take it from the package itself, for example its construction plans, never written by hand), each statement separated by `--> statement-breakpoint`, ending with exactly these lines (the last ends with a line break; UTF-8 without a byte-order mark):
   ```sql
GRANT USAGE ON SCHEMA pgboss TO nexus_app;
--> statement-breakpoint
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA pgboss TO nexus_app;
--> statement-breakpoint
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA pgboss TO nexus_app;
--> statement-breakpoint
GRANT EXECUTE ON ALL FUNCTIONS IN SCHEMA pgboss TO nexus_app;
--> statement-breakpoint
ALTER DEFAULT PRIVILEGES FOR ROLE nexus_owner IN SCHEMA pgboss GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO nexus_app;
--> statement-breakpoint
ALTER DEFAULT PRIVILEGES FOR ROLE nexus_owner IN SCHEMA pgboss GRANT USAGE, SELECT ON SEQUENCES TO nexus_app;
--> statement-breakpoint
ALTER DEFAULT PRIVILEGES FOR ROLE nexus_owner IN SCHEMA pgboss GRANT EXECUTE ON FUNCTIONS TO nexus_app;
   ```
   If pg-boss's SQL needs a right `nexus_owner` does not have (for example creating an extension), STOP and mark BLOCKED with the exact message. Your change number is the next free one; Claude renumbers at merge when needed. Do not run `db:migrate`.
3. **Queues** (`src/jobs/queues.ts`): `queueSql(name: string): string` gives back the SQL pg-boss 12.38.0 runs to create one queue with its default settings; database changes (and the tests) run it as `nexus_owner`. The app never creates a queue, a table or anything else: pg-boss starts without installing or changing its schema, and with whatever it would otherwise create at run time (for example per queue) switched off. If that is not possible with 12.38.0, STOP and mark BLOCKED, saying what it would create.
4. **Jobs** (`src/jobs/jobs.ts`):
   - `JOB_POOL_SIZE`: pg-boss's own connection pool size, a constant from 1 to 4 (2 is right); pg-boss connects as `nexus_app` with the address in `DATABASE_URL_APP` and the schema `pgboss`.
   - `defineJob<T>({ name, retries, handle })` gives back a plain definition (no registry); `handle(data: T)` returns nothing.
   - `sendJob(definition, data)` refuses with `a job needs the company` when there is no request context or it has no company; it sends `{ companyId, data }` to the definition's queue with `retryLimit` = its `retries`, and gives back the job's ID.
   - `startJobs({ jobs, logger })` starts pg-boss once and registers each definition's handler (the only `.work(` in the code). Each job runs in `runWithContext({ requestId: <the job's ID>, background: true, companyId })` and `inCompanyTransaction(companyId, () => handle(data))`. A failure is logged as `logger.error({ err: error, jobId }, 'job failed')`, kept with `recordError(error, 'worker')` in the job's context (`logger.warn(..., 'error not recorded')` if that fails), and thrown back to pg-boss as `new Error(safeErrorMessage(error))` with no `cause`, so its stored output holds only the cleaned message. It gives back `{ stop(): Promise<void> }`, which waits for running jobs, stops pg-boss and leaves no timer.
5. **Worker:** `worker.ts` keeps its first line, starts the delivery first, then `const jobs = startJobs({ jobs: [], logger });`, and on SIGTERM or SIGINT awaits `jobs.stop()`, then the delivery's `stop()`, then `closePools()`, then exits 0.
